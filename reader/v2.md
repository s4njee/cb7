## P0 — reliability and performance

---

## 1. Debounce and flush reading progress — S

Comic, PDF, and EPUB readers no longer call `putProgress` on every turn. A shared trailing debounce (~800 ms) keeps the latest body per book, drops non-monotonic page/percent within a session, and flushes on reader unmount, document hide, and `pagehide`. Fake-timer vector tests cover burst collapse, immediate flush, and multi-book drain.

**New files**

- `src/lib/progressWrite.ts`
- `src/lib/progressWrite.test.ts`

**Modified files**

- `src/lib/api.ts` (`scheduleProgress`, `flushProgress`, `flushAllProgress`)
- `src/components/ComicReader.tsx`
- `src/components/PdfReader.tsx`
- `src/components/TextReader.tsx`
- `src/components/Reader.tsx` (flush on session end)

## 2. Make local catalog updates transactional under concurrency — M

Catalog mutations now serialize through `catalog_write` so mutate → snapshot → atomic `.tmp`/rename cannot finish out of order. `mutate_catalog` covers progress, favorites, covers, and page-count cache; import/delete/download hold the write lock across their catalog edits. A tokio concurrency test interleaves progress, favorite, and cover updates and asserts the final on-disk catalog keeps all fields.

**New files**

- *(none — helpers live in `local.rs` / `state.rs`)*

**Modified files**

- `src-tauri/src/state.rs` (`catalog_write` mutex)
- `src-tauri/src/local.rs` (`write_catalog_snapshot`, `mutate_catalog`, `save_under_write_lock`, concurrent mutation test)

---

## 3. Coalesce duplicate media-cache misses — M

The media proxy registers a per-cache-key in-flight entry before fetching. Concurrent misses await the leader’s `Notify`, then re-read the disk cache instead of issuing parallel upstream downloads—the pattern that shows up when the grid, continue card, thumbs, and preloader hit the same cold URL.

**New files**

- *(none)*

**Modified files**

- `src-tauri/src/state.rs` (`cache_inflight`, `CacheInflight`)
- `src-tauri/src/proxy.rs` (coalesce path + unit test)

## 4. Virtualize long comic/PDF scroll surfaces and thumbnail strips — L

Fixed-size virtual windows with overscan and before/after spacers replace one React node per page for comic continuous mode, the comic thumbnail strip, and PDF scroll mode. Current page tracking uses stride math instead of scanning every mounted slot, so 1,000+ page books stay bounded.

**New files**

## 5. Bound PDF canvas memory explicitly — M

Scroll-mode PDF painting honors a device-class budget (stricter on tablets). Pages that leave the keep-set cancel render tasks and zero canvas dimensions so pixel buffers can be reclaimed; overscan is smaller on phone/tablet than desktop.

**New files**

- `src/lib/pdfMemory.ts`

**Modified files**

- `src/components/PdfReader.tsx`

## 6. Add an offline progress outbox — L

Failed server progress PUTs (transport / 5xx) enqueue the latest body per server/user/book in `localStorage`, coalescing intermediate turns. Flush runs on `online` and when the app becomes visible; conflict policy pushes furthest within the same reading session and marks larger cross-session disagreements for explicit resolve instead of silent overwrite. Open session ids are tracked via `beginReadingSession` / `endReadingSession` on the reader shell.

**New files**

- `src/lib/progressOutbox.ts`
- `src/lib/progressOutbox.test.ts`

**Modified files**

- `src/lib/api.ts` (outbox-aware `putProgress`, `syncProgressOutbox`, session helpers, re-exports)

## P2 — iOS Files / share integration — M

Open In, the share sheet, and Files “Open with CB8” now deliver EPUB/PDF/CBZ/CBR into the owned library: `bundle.fileAssociations` registers the types, `RunEvent::Opened` stores cold-start URLs and emits `shelf://opened-files` for live opens, and the frontend always **copies** via `local_import` (never security-scoped re-reads) then opens the first book.
